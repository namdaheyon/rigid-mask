# rigid_mask_ros

ROS1 Noetic wrapper for the CVPR 2021 RigidMask inference model. This port is
kept separate from `macaron_8` and does not install or update conda, pip, CUDA,
or system packages.

## Local compatibility replacements

- Kornia geometry calls: small pure-PyTorch implementation in `geometry.py`
- Detectron2: removed (it was only used by the upstream visualization script)
- compiled DCNv2: `torchvision.ops.deform_conv2d`
- compiled NG-RANSAC: OpenCV `findEssentialMat` and `recoverPose`
- `torch.hub`: removed; MiDaS architecture and weights are loaded locally

The unmodified portions of RigidMask are vendored under
`rigid_mask_ros/vendor/rigidmask` and retain the upstream MIT license.

## Run

```bash
cd /home/macaronfrom8/catkin_ws
source devel/setup.bash
roslaunch rigid_mask_ros rigid_mask.launch
```

This launch starts only the camera RigidMask node. To start RigidMask,
`dh_lidar`, and the prepared RViz view together:

```bash
roslaunch rigid_mask_ros fusion_visualization.launch
```

The integrated view uses the full front-camera frame and requires these existing
vehicle inputs:

- `/camera/1/image_raw/compressed`
- `/velodyne_points`
- `/current_pose` (`geometry_msgs/PointStamped`, `z` is heading in radians)

RViz legend:

- fusion points red: camera mask says dynamic
- fusion points blue: camera mask says static
- fusion points gray: no synchronized/projectable mask evidence
- labeled sphere: final tracked `DYNAMIC`, `STATIC`, or `UNKNOWN` decision
- cyan arrow: LiDAR-measured travel direction
- yellow label: track ID and speed in km/h

The integrated launch opens RViz only. Camera 1's full-frame fusion overlay is
available as an RViz Image display (disabled by default so it does not cover
the 3D scene); no separate camera viewer is started.

The launch file invokes the existing interpreter at
`/home/macaronfrom8/anaconda3/envs/torch/bin/python`. Override it without
changing the environment:

```bash
roslaunch rigid_mask_ros rigid_mask.launch python:=/path/to/python
```

Standalone RigidMask input in the current front-only configuration:

- `/camera/1/image_raw/compressed`

Only the compressed-message receiving pattern from `traffic.py` is shared.
There is no ROI/crop step: every decoded image is passed as a full frame and
the mask is resized back to that frame's full width and height.

Output (`sensor_msgs/Image`, `mono8`, 255 = dynamic):

- `/rigid_mask/camera_1/dynamic_mask`

LiDAR support input generated by `dh_lidar`:

- `/rigid_mask/camera_1/lidar_support`

Full-frame camera/LiDAR fusion output (`sensor_msgs/Image`, `bgr8`):

- `/rigid_mask/camera_1/fusion_overlay`

The overlay contains RigidMask only near projected non-ground LiDAR returns,
projected object points, the final `DYNAMIC`, `STATIC`, or `UNKNOWN` state,
tracking ID, speed, signed vehicle-relative direction angle, and a cyan
direction arrow. Sky and road areas without LiDAR support are not tinted. Red
means dynamic, blue means static, and gray means unknown. No image is cropped.

`DYNAMIC` and `STATIC` are decided exclusively by the latest matched RigidMask
value. LiDAR motion never vetoes, replaces, or corrects that decision. LiDAR is
used for object position/ID association and for measured speed and direction;
frames between slower mask observations retain the last confirmed mask state.
The network's mask is synchronized to its first/reference image (the coordinate
frame in which RigidMask predicts foreground), so projected LiDAR points are no
longer sampled against the second image by mistake.

Only camera 1 runs the GPU model. Its incoming queue keeps the newest adjacent
pair, so overload drops stale work rather than accumulating latency. A stopped
camera bypasses the degenerate Essential-Matrix path and uses global-motion-
compensated local image change over a 0.1 s frame baseline; this keeps fixed
poles/background static while detecting locally moving objects without a slow
dense-flow pass. Detected local motion is retained for 0.3 s so duplicated
simulator render frames do not immediately turn a moving object static. If
moving-camera pose recovery fails, image-difference fallback is used only when
`/current_pose` also says the ego vehicle is stopped. This pose speed selects
the inference path and is never used as object dynamic/static evidence. The
first frame publishes no decision, so `dh_lidar` retains the last valid state
(or `UNKNOWN`).
LiDAR clustering/fusion is limited to 20 m by the integrated launch.

With only camera 1 enabled, a current LiDAR object outside the front camera's
field of view remains `UNKNOWN`; the node does not invent a static decision
without camera evidence. Stale, unclassified missed tracks are hidden from RViz
to avoid presenting old gray labels as current detections.

RigidMask is a dense convolutional model, so it still evaluates the complete
front frame internally. The published mask is gated to LiDAR-supported pixels;
the main inference-load reduction comes from running only camera 1.

The upstream instance-detection branch is skipped after foreground-mask
generation because object instances and velocities are supplied by LiDAR in
`dh_lidar`. This preserves the mask used for fusion while reducing GPU work.

Calibration is read from `my_lidar_pipeline`'s
`config/calibration/calibration_result.yaml`. Runtime parameters, thresholds,
topics, and local model paths are in `config/rigid_mask.yaml`.
